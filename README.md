# 🛡️ مدیر گروه سروش‌پلاس

ربات مدیریت گروه برای **حساب شخصی سروش‌پلاس** با قابلیت مدیریت اعضا، ضداسپم، حذف تبلیغات، قفل دسترسی‌ها، پاسخ خودکار، زمان‌بندی چت و ثبت گزارش‌های مدیریتی.

> این پروژه یک **Userbot** است؛ یعنی با حساب شخصی سروش‌پلاس وارد می‌شود و فقط باید در گروهی استفاده شود که همان حساب مجوز مدیریت آن را دارد.

## 📦 نصب محلی

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[soroush,dev]"
Copy-Item .env.example .env
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[soroush,dev]"
cp .env.example .env
```

اگر قبلاً نسخه‌ای نصب شده که فقط `soropy` داشته است:

```bash
pip install -e ".[soroush]"
```

## ⚙️ تنظیمات

فایل `.env.example` را به `.env` کپی کنید و مقادیر واقعی را فقط روی سیستم خودتان یا Railway Variables قرار دهید.

نمونه:

```env
SOROUSH_GROUP_ID=<EVENT_GROUP_ID>
SOROUSH_GROUP_TARGET=@your_group_username
SOROUSH_PHONE=+98xxxxxxxxxx
SOROUSH_BACKEND=websocket

DATABASE_PATH=/data/manager.db
SESSION_DIR=/data/session

CHAT_SCHEDULE_TIMEZONE=+03:30
CHAT_SCHEDULE_CHECK_SECONDS=20
OUTGOING_COMMAND_CHECK_SECONDS=3

CALL_MEMBERS_LIMIT=500
CALL_MEMBERS_BATCH=20
CALL_MEMBERS_DELAY_SECONDS=1.5
```

### تفاوت `SOROUSH_GROUP_ID` و `SOROUSH_GROUP_TARGET`

برخی رویدادهای لحظه‌ای ممکن است شناسه داخلی عددی گروه را ارسال کنند، درحالی‌که عملیات API با Username/Target گروه انجام شود.

در این حالت هر دو را تنظیم کنید:

```env
SOROUSH_GROUP_ID=<NUMERIC_EVENT_ID>
SOROUSH_GROUP_TARGET=@your_group_username
```

- `SOROUSH_GROUP_ID`: محدودکردن پردازش رویدادها به گروه موردنظر
- `SOROUSH_GROUP_TARGET`: عملیات API و بررسی سطح دسترسی سمت سرویس

## ☁️ اجرای دائمی روی Railway

فایل‌های `railway.json` و `Dockerfile` ساخت و اجرای Worker را تنظیم می‌کنند.

برای حفظ SQLite و Session باید یک Volume روی مسیر زیر متصل شود:

```text
/data
```

ورود اولیه از Railway SSH انجام می‌شود:

```bash
python -m splus_manager --login-only
```

راهنمای کامل در فایل زیر قرار دارد:

```text
RAILWAY_DEPLOY_FA.md
```

## 🔒 امنیت Repository عمومی

این Repository می‌تواند Public باشد، اما اطلاعات زیر **نباید** داخل GitHub قرار گیرند:

- `.env`
- شماره تلفن واقعی
- کد ورود
- Session
- دیتابیس واقعی
- Logهای حساس
- Token / Secret
- شناسه خصوصی گروه، در صورت حساس بودن

اگر Credential یا Session قبلاً Commit شده، حذف فایل از آخرین Commit کافی نیست؛ Credential را تعویض و Git History را نیز بررسی کنید.

## ⚠️ نکات مهم

- حساب اجراکننده باید دسترسی مدیریتی کافی داشته باشد.
- برای عملیات حساس، سطح دسترسی ادمین باید سمت سرویس دوباره بررسی شود.
- Session را هرگز عمومی نکنید.
- برای اجرای Railway فقط **یک Replica** استفاده کنید.
- نرخ فراخوانی اعضا را محافظه‌کارانه تنظیم کنید.
